# Event Engine — интеграция

## Компоненты

- `src/core/event_engine.py` — единая публикация `PygramEvent`.
- `src/core/qt_signal_bridge.py` — доставка событий в GUI-поток через Qt `QueuedConnection`.
- `src/transport/file_transport.py` — один watchdog Observer может следить за несколькими каталогами.
- `src/core/tick_engine.py` — единый планировщик резервных проверок.
- `src/core/sync_engine.py` — централизованные синхронизационные worker-потоки, дедупликация и очередь.

## Маршрутизация событий

Открытый чат наблюдает за `message/<chat_id>`, `.status` и `.meta`.

- `message/<chat_id>/*.bin` — синхронизация новых/изменённых сообщений; физическое удаление удаляет запись из локальной БД и модели.
- `.status/reactions/<chat_id>_*.json` — обновление реакций.
- `.status/read/<chat_id>_*.json` — обновление отметок прочтения.
- `.status/deleted/<chat_id>.json` — применение маркеров удаления.
- `.status/<fp16>.json` — обновление присутствия/набора текста собеседника.
- `.meta/<chat_id>.*` — обновление метаданных группы, списка участников и доступности группы.

## Резервная сверка

- открытый чат: каждые 5 секунд;
- присутствие: каждые 2,5 секунды;
- список чатов: каждые 3 секунды.

Эти интервалы — страховка от пропущенных файловых уведомлений. Основной путь обновления — события.

`SyncEngine` ограничивает число одновременно работающих worker-потоков тремя. Повторный событийный запрос для уже синхронизируемого чата вызывает один дополнительный проход; периодический запрос не создаёт бесконечную очередь повторов.
